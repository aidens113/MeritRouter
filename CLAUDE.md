# SwitchYard Router: Claude Code specifics

Multi-agent framework: a supervisor (Claude Code over MCP, or SwitchYard's own on models you
choose) delegates bounded work to free and optionally paid worker models, with routing, budgets,
roles, a shared brain, and per-line attribution enforced in code. `AGENTS.md` (imported above)
holds the binding agent rules: roles, workflow modes, delegation, boundaries, validation,
branches, and pushing.

## Layout

- `packages/router` (`switchyard-router`): library, CLI (`switchyard`), MCP server, charters,
  presets (`examples/presets`, generated by `scripts/build-presets.mjs`), eval suite (`evals/`).
  - `src/core` service, executor, scheduler; `src/gateway` gate and the direct path;
    `src/providers` registry, vault, client, discovery, key state, limits, health; `src/paid`
    spend and paid budgets; `src/routing` tiers and selection; `src/scoring` rulebook and classifier;
    `src/harness` agent loop and tools; `src/runners` per-role runners; `src/brain` shared
    knowledge; `src/attribution` commits, blame, undo; `src/models` catalog and scanning;
    `src/admin/insights.ts` the panel's API (a facade re-exporting `admin/jobs.ts`,
    `admin/sessions.ts`, `admin/job-plans.ts`, `admin/job-team.ts`, `admin/calibration.ts`); `src/verification`
    contracts, review, calibration; `src/sessions` session logs and resume; `src/operations`
    backup, daemon, service install; `src/cli/` terminal formatting for `cli.ts`;
    `src/gateway/capacity.ts` provider slots; `src/admin/job-metrics.ts` team metrics;
    `src/projects` project registry and `ProjectContext`; `src/mcp` MCP tools and transports
    (stdio, Streamable HTTP); `src/web` web search backends (pool), SSRF-guarded fetch, ledger.
- `apps/panel`: Next.js panel (`pnpm --filter switchyard-panel seed:demo` for demo data).
- `docs/`: setup, roles, operations, decisions, working documents.

## Commands

- `pnpm install` at the repo root; `pnpm -r typecheck`, `pnpm -r test`, `pnpm -r build`.
- Router tests: `cd packages/router && npx vitest run` (the package `test` script builds first; the
  MCP test needs `dist/`).
- Panel check: build the router, `pnpm --filter switchyard-panel build`, seed the demo, start on a
  spare port, curl pages, screenshot with headless Chrome
  (`"C:/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --screenshot=...`).

## Environment gotchas

- Node 22.11: better-sqlite3 is pinned to 12.x (13.x segfaults on Windows/22.11); Vitest 3.2 +
  Vite 6 (Vitest 4/5 need Node >= 22.12).
- Windows `core.autocrlf=true`: fixture checkouts get CRLF. Tools must preserve line endings;
  tests compare with `\r?\n`.
- Close every `Switchyard`/database in tests before deleting temp dirs (Windows EBUSY).
- Tests must use temp brains (`brain.path` relative to the test config), never the default
  `~/.switchyard/brain`.
- Symlink tests self-skip on accounts without symlink privileges.
- Multi-line patches through bash heredocs mangle backslash escapes; write a patch script file or
  use the edit tool for regex-heavy code.
