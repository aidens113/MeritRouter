# Report: model-unavailable-recovery
## Outcome
Done: definite free model/account refusals no longer consume the transient endpoint fallback allowance; unknown-model responses fall through to other eligible routes.
## What changed and why
- `packages/router/src/gateway/gate.ts`: original code capped all free failed endpoints at routing.max_endpoint_fallbacks (default3). Three rollout/not-in-plan refusals prevented a fourth healthy route from being tried. A separate freeFallbacks counter now caps ordinary transient endpoint attempts, while definite account/model refusals continue through the finite candidate list. Physical dispatched counts, admission/receipts and paid max_paid_attempts remain unchanged.
- `packages/router/src/gateway/direct.ts`: DirectOutcome.failed has optional unavailable boolean, set only for definite nonconsuming ProviderError reasons not_in_plan/unknown_model/auth_invalid/out_of_credits. Unknown-model now belongs to endpoint fallback kinds, without retrying the same endpoint/key. Existing per-key/model refusal cache now also records definite unknown_model errors without changing its JSON schema. Unknown-model rotates to another key before falling through to the next endpoint. `providers/keys.ts` caches only the refused model/key; key/provider stay enabled. Gate exclusion text is now model unavailable with every provider key, accurately covering both404 and plan refusals; two existing providers-routing assertions were updated. Uncertain consumed errors still consume the ordinary retry allowance.
- `packages/router/tests/model-unavailable-recovery.test.ts`: actual HTTP FakeProvider + Gate prove four refused endpoints followed by healthy succeeds, every physical request recorded, key remains valid, subsequent calls skip all cached rollout/plan/unknown-model refusals, clearing key state restores probes, a separate key can still serve a404-hidden model, exhausted finite pool attempts each route once, disabled paid never escalates, server failures retain three-attempt cap, real submitted task still exhausts its three-request budget exactly.
