## Contract / root integration
New gateway/request-capture.ts exports RequestCaptureViewSchema/RequestCaptureView, CapturePayloadSchema, CapturedInputSchema/CapturedInput, CapturedOutputSchema/CapturedOutput, CaptureOutcomeSchema/CaptureOutcome, CaptureOmissionSchema/CaptureOmission, RequestCaptureStore, projection types/functions and CAPTURE_LIMITS. Normalized input uses explicit model/messages/maxTokens/temperature/tool definitions/toolChoice/responseFormat/webSearch metadata; output is observed content/tool calls/finishReason. It is not serialized provider HTTP content or accepted task output.

Gate.captures defaults to RequestCaptures(db, runtime clock), with optional final constructor injection for tests. RequestCaptures.read(id,{project:string|null}) returns scoped RequestCaptureView or null for unknown/wrong scope; explicit null only accesses genuinely unscoped requests. purgeProject(project):{captures,bytes} removes all records whose stored owner or private participant project set includes the project, transactionally. Root must call this BEFORE project request anonymization; root owns admin/public exports and project deletion integration. prune(limit=64) is bounded1..256 and never changes accounting rows.

Each admitted key/endpoint attempt has its own requestId and capture; executionId reuse never overwrites another request. Existing journal replay remains separate provenance. Classifier and completion shared batches capture one physical request, not one copy per member/session. Mixed/unknown participant scope stores metadata only, never content; reads also recheck authoritative participant project set. Missing historical record stays unavailable/not_captured.

## Ordering / failures
Capture input and dispatch-intent writes are awaited after ledger reservation; AbortSignal and persisted lease/cancel/deadline are checked afterward immediately before provider call. Capture writes/projection errors are guarded outside provider error classification and never cause retries/fallback or change paid accounting. Terminal capture is awaited in reconciliation finally, preserving observed provider response even when ledger settlement throws; original persistence error escapes. A policy-discarded response remains observed and policyViolation=true. Gate's existing in-flight drain includes capture, so service close cannot close DB first. A missing terminal payload on a finished request reads partial/capture_failed; inability to write any record is honestly indistinguishable from not_captured.

## Approved fixed defaults / data handling
Default-on, fixed internal policy per supervisor brief: record1MiB, input512KiB, output256KiB;256messages,64tools,64 input/output calls,depth16,10k whole-payload nodes,128omissions,8MiB combined input/output text scan allowance (half per projector). Individual text fields64KiB maximum. Bounded structural preflight occurs before recursive schema validation; UTF-8 JSON byte sizes are checked again before persistence/read. Private JSON metadata+scope are counted with256byte row overhead within record/global budgets. Tool schema subtrees use conservative extra depth/node headroom for envelope/omission/response structure.

Retain7days,128MiB/project,512MiB global,10k rows. Small bounded pruning drops expired payloads or oldest records for quota/count headroom, preserving model requests/charges/paid rows. Lack of headroom refuses observational capture rather than accounting. TTL/eviction tombstones contain no model content and count toward limits; oldest tombstones can be removed, after which absence is not_captured.

Images/data URLs become image_omitted markers; no locator or bytes are retained or fetched. No ProviderRequest/provider config, credentials/account ids, auth/telemetry headers, cache key, environment, raw HTTP body or storage filesystem/artifact location is projected as metadata. Strings in user/model content can themselves contain secrets/paths/URLs: they remain private literal content; no general sanitization claim. Bounds preserve ordering and recent messages with original indices; shortened/dropped values carry omission metadata and partial status. originalBytes is the sum of complete projected input/output JSON sizes only when neither was omitted; otherwise null, not a fabricated original size. Per-field omissions can retain known original UTF-8 size.
