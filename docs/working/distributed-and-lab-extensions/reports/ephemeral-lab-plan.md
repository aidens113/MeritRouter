# Ephemeral task Lab integration plan

Status: Proposed; read-only source inspection, not implementation or runtime verification.
Baseline: root 77914fc, 2026-10-22. Browser contract read from the frozen roadmap-labs worker report; that source is not yet in root.
Owner: worker link_completion. Only this report is owned/changed.

## Findings that determine the integration

- `runners/coding/finish.ts:finishCoding` is shared by native and external coding. It collects/stages the diff, enforces allowed/protected paths, writes a patch artifact, runs declared command checks, and returns `RunOutcome`. `evidence.revision` is **git write-tree**, not a commit. Native commits model edits in `native.ts:onResponse`; external commits final edits before finishCoding in `index.ts`. Do not manufacture an unattributed commit merely to make a Lab source.
- `core/executor.ts:runSingle` verifies the returned outcome with `verifyWithReview`, may repair/escalate in the same claimed run, then records via `TaskStore.finish`. Twin runs call the same verifier independently through `runTwins`. `run_count` increments on task claim, not each quality repair/twin; neither task id nor run_count uniquely identifies a coding attempt.
- `workspaces/worktree.ts:prepare` creates a fresh detached directory per attempt but UPSERTs `workspaces` by task_id; the table retains only the latest attempt pointer. `resumeWorkspace` can restore a session pointer. Neither that latest row nor a directory-name prefix is a sufficient destructive-cleanup identity.
- `harness/integration-tools.ts:integrationGateAfter` compares the first check revision with HEAD^{tree}; `integrationTargets` reads the latest workspaces row and its current HEAD. Lab check revisions are commits. Adding raw Lab records to WorkerResult.checks would silently break this tree/commit contract.
- `workspaces/merge-queue.ts` captures source base/head and can rebase the source worktree on conflict. A passing pre-integration Lab result is evidence for the submitted source, not proof of a later rebased/merged candidate.
- `labs/lab.ts:createLab` currently resolves configured target branches, creates all project Lab worktrees, snapshots recipe/env, allocates ports, and runs setup. That is a retained feature Lab API, not an attempt snapshot API. `binding.ts` claims one retained Lab for a root supervisor team and overlays its repository paths; ephemeral verification must bypass that team claim/overlay mechanism while retaining the team's effective source paths when applicable.
- Labs already have service ownership tokens, positive listener proof, birth/command-checked termination, private process-proof files, durable control operations and a dedicated serve owner. API/model workers must continue to queue operations rather than own service leases.
- `Scheduler.recover` marks expired tasks interrupted and can automatically resume them, while `LabManager.recover/tick` can adopt/restart ordinary retained services. Ephemeral desired-stop recovery must run before that generic adoption/restart, and old-attempt cleanup must not block a new attempt's independent directories.
- `labs/retention.ts:pruneTaskWorktrees` considers terminal tasks/ended ancestors, configured physical source and registered clean worktrees. It has no attempt-Lab dependency guard today. `LabManager.destroyLab` removes the entire Lab root, including browser artifacts; ordinary stop retains port reservations. Neither behavior directly meets automatic teardown plus retained attempt evidence.

## Chosen opt-in and authority contract

Keep WorkerTask.lab unchanged: it still denotes the inherited retained feature Lab/team. Add an independent task constraint `constraints.labChecks?: LabName[]` (unique, 1..10). It selects **names only**, never recipe bodies, commands, environment, paths, ports, browser executable, source revisions or retention policy. It is legal only for coding profiles with isolated_worktree and valid writableRepository/allowedPaths. It may coexist with WorkerTask.lab: the feature Lab remains the team's target, while this task gets a separate verification Lab from its worker attempt commit. A completion/read-only/supervisor task cannot opt into this worker-attempt mechanism.

Add human project configuration `labs.ephemeral: {enabled: boolean = false, checks: LabName[] = []}` to ProjectLabsSchema (unique max 10). Enabled requires a configured project.lab recipe and a nonempty allowlist of existing checks. A task must explicitly name a nonempty subset of that allowlist; do not auto-enable every delegated task or inherit these selections into sub-supervisor jobs. This separates project authorization from model selection. Project recipe setup/services/checks remain trusted operator commands, subject to the existing ownership and resource rules; this is not arbitrary-code sandboxing.

Use the current declared project recipe snapshot. Start its declared service graph and execute only selected checks. Reject a task if any recipe setup/service/check repo or repo placeholder used by that snapshot is outside task.repositoryAliases; do not silently grant project-wide repositories to a narrow task. Require the entire recipe repository set to fit the task in the first implementation. A future explicitly named recipe subset can reduce this restriction without widening authority.

Update core/validate.ts and project cross-reference validation; repeat authorization against the durable recipe/selection snapshot before execution. Validate all new DTOs, rows, markers and results with zod. A service/task boundary must reject forged/extra fields. Invalid tasks fail before provider/model dispatch; unavailable Lab capacity waits/fails as an infrastructure condition within the existing deadline, never becomes a successful skipped check. Existing constraints.checks and criterion check mappings retain their command meaning.

## Durable attempt and immutable source contract

Append migrations; do not edit applied entries. Proposed data additions:

1. `task_workspace_attempts`: id TEXT PK (new opaque twa_ id), task_id FK tasks, project_id, run_count INTEGER CHECK >=1, session_id nullable, execution_id unique nullable, lease_owner, source_repositories_json, writable_alias, source_worktree, source_base, submitted_commit nullable, submitted_tree nullable, patch_digest nullable, state, created_at/updated_at. Unique execution_id when non-null; indexes task_id/run_count and task_id/state. State: preparing/working/submitted/superseded/closed. Source JSON is a validated bounded alias map with physical repository identity, effective source path, pinned base/head and Git common-directory identity. Private absolute paths never become model DTOs. Generation is id plus the claimed run_count/lease_owner; do not require global task active-attempt uniqueness because twins legitimately overlap.
2. `labs.kind TEXT NOT NULL DEFAULT 'retained' CHECK(kind IN ('retained','task_attempt'))`; add optional kind to hydrated existing records via the migration default, not permissive unknown input. Keep LabState operational states unchanged.
3. `lab_task_attempts`: lab_id PK/FK labs, workspace_attempt_id UNIQUE/FK, task_id FK, project_id, run_count, task_lease_owner, desired_state CHECK running/stopped, phase CHECK queued/creating/starting/checking/stopping/retained/cleanup_blocked/pruned, selected_checks_json, immutable_heads_json, submitted_tree, patch_digest nullable, recipe_digest, deadline_at, result_json nullable, cleanup_error nullable, created_at/updated_at. Persist lease/generation CAS fields for the control owner (owner_id/owner_until) if not reusing lab_operations ownership for every transition. No FK delete cascade that discards evidence/process proof.
4. `lab_attempt_processes`: id, lab_id, workspace_attempt_id, kind CHECK service/setup/check/browser, logical_name/check_id, private token, pid nullable, birth/command/proof reference nullable, spawn state, created_at/updated_at. Needed for recovery of auxiliary setup/check/browser children, not just lab_services. A killed owner cannot execute finally. Do not claim killed-owner cleanup from current browser_check_closed events alone: browser launch tokens/proofs are not currently a reusable durable process registry. Existing service rows can remain authoritative service state, with a linked process registration.

Create an attempt registration in prepareWorkspace before worktree creation, return its id with Workspace, and pass the handle through both coding runners into finishCoding. Both runners currently generate executionId after preparing their workspace: move that id allocation before prepare/resume and change their calls to prepareWorkspace(ctx, {executionId}) / resumeWorkspace(ctx, recorded, {executionId}); register that id once before filesystem mutation. Keep workspaces as the compatibility/latest-pointer view. Repair gets a fresh attempt id even under one run_count. Resume registers a **new verification attempt** tied to the resumed workspace plus priorAttemptId for history; it never resurrects an old attempt's running services. A twin has its own id/session/worktree; result selection must record the winning source pointer rather than trusting whichever UPSERT ran last.

Pin read-only context repository commits at workspace preparation (explicit normalized baseCommits where supplied; otherwise resolve actual effective source HEAD once). For feature-Lab tasks use contextForTask's effective repository paths, then validate Git common-directory membership against the configured project source. Do not read fresh target HEADs at Lab creation. The writable repository source is the attempt's attributed submitted HEAD. At finish require clean working tree/index and HEAD^{tree} equal the staged submitted tree; scope violations, missing attribution/commit, dirt or mismatched objects refuse runtime verification. If checks produce tracked changes, refuse rather than commit evaluator changes as worker output. Store both commit SHA and tree SHA; pin all aliases. A later unrelated advance of the original project/feature target branch does not rewrite these immutable context snapshots or automatically invalidate them; checks and integration compare stored attempt objects, not fresh external target HEADs.

Create distinct lab-only worktrees/branches from those exact objects with no target checkout mutation: `<storage>/labs/<project>/<generated-attempt-name>/repos/<alias>` and `switchyard/task-lab-<project-hash>-<attempt-id-suffix>-<alias-hash>`. Persist full generated branch names before Git mutation, validate length and full object ids, invoke Git argv with --end-of-options where supported, verify Git common dir/registered worktree/path and exclusive ownership marker. Marker includes labId, attemptId, taskId and generation. Each Lab gets independent data directories and port reservations. Never use the worker source worktree as a service cwd, reset it, or delete it on ephemeral teardown.

  heads: Record<string,string>; submittedTree: string; patchDigest: string | null;
  recipeDigest: string; status: 'passed'|'failed'|'environment_failure'|'cancelled';
  cleanup: 'complete'|'blocked'; artifactRefs: string[]; }

Registration/submission atomically check tasks.project_id, live lease_owner/run_count/state/cancel/deadline and ownership of the stored source attempt; caller-provided paths/heads are verified against stored Git/worktree identity. A lost owner cannot submit a replacement attempt or renew its resources. Internal queue input carries only validated attemptId; the serve owner resolves persisted trusted snapshots. Expose internal attempt_check/attempt_cleanup operations separately from public LabControl body parsing, or enforce an internal dispatcher that cannot be reached by model tools/admin arbitrary JSON. Preserve normal create/start/stop/control contracts. A stopped ephemeral Lab cannot be started/refreshed/promoted/team-bound through retained-Lab APIs.

Primary normal-path hook: finishCoding, after scope collection and normal command checks, before returning RunOutcome to verifyWithReview. Only completed, in-scope, committed outcomes run the selected Lab checks; non-completed outcomes mark them not_run/cancelled and request cleanup if any allocation exists. Start/ready/check on the dedicated Labs supervisor, persist exact all-repository HEADs before and after each selected check and final cleanliness, then **stop all services/auxiliary processes before returning successful evidence**. A cleanup refusal blocks success/integration and retains proof. Normal model budgets, Gate usage, attribution, repair allowance and task deadline remain authoritative; the Lab performs no model requests and cannot extend the task deadline. Keep cleanup on an independent bounded cleanup signal so task cancellation does not cancel termination itself.

Add optional structured `WorkerResult.taskLab` evidence and corresponding RunEvidence/CheckedResult field; keep WorkerResult.checks revisions as tree SHAs and normal command strings. Add required deterministic named check `ephemeral_lab_checks` when constraints.labChecks is present. Extend AcceptanceContract with optional/default-empty declaredLabChecks and immutable recipe digest; compile them once. The check verifies selection completeness, passed exit codes, no killed flags, matching source commit/tree/digest/all heads, and cleanup complete. Failure is unmet; missing/stale/environment failure cannot auto-pass or be bypassed by an independent reviewer. Existing decide/repair logic can request the same bounded repair according to policy. Check-criterion support can be a later explicit `labChecks` criterion field; first unit treats these as an additional required task-wide gate, without redefining existing criterion checks.

At executor record/TaskStore.finish and integrationGateAfter, validate that evidence belongs to the selected outcome attempt. IntegrationTargets must use that attempt's recorded source worktree/base/commit for opted-in tasks, not latest workspaces. Before enqueue reject source dirt, moved HEAD/tree or changed owned Lab context heads relative to the persisted snapshot; a human accept:true cannot override missing/failed required Lab checks. No opt-in leaves old execution/result/integration behavior intact. MergeQueue conflict rebase changes the source candidate: never relabel old checks current. Bounded first implementation should refuse automatic rebase for opted-in task items and redelegate on the new base, or add a dedicated awaited revalidation hook before repick. Recommended first unit: redelegate with labChecks preserved; keep normal auto-rebase for ordinary tasks. Existing job checks still run after integration and verify the combined branch, which pre-integration Labs alone cannot do.

## Teardown, kill recovery and evidence retention

Normal success, failed assertion/service/setup, task cancel, deadline, capacity defer, repair/escalation, twin loser, thrown error and executor disposal all request desired_state=stopped idempotently for that exact attempt. In-flight check cancellation must be observed by the executing serve owner, not merely stop the waiting API promise. Serve polls task state/run_count/lease_owner/expiry/cancel/deadline during work; terminal/expired/superseded generations abort checking and stop. Cleanup follows per-lab operation ownership plus attempt CAS, never a task-id path scan. Repeated cleanup may observe already-gone processes as success only after checking all recorded known children.

On startup/tick reconcile task-attempt desired state **before** generic retained Lab recovery/service restart. Expired task owner or expired operation owner triggers takeover only after its lease expires; new attempt id cannot renew the old resources. Task scheduler auto-resume may create another independent attempt, but the old services stay desired-stopped. Never transfer old port/data resources to the new attempt or adopt them as running application state. Actual remote/multi-host recovery is outside this single-host design.

Persist spawn intent + nonce before process creation, then actual PID/birth/command proof before enabling child commands/navigation. A wrapper starts dormant until registration is durable. Handle the crash between spawn and PID persistence: recover by exact wrapper marker+durable nonce and validated creation/command identity, with bounded OS enumeration; ambiguity retains evidence and reports cleanup_blocked. No broad PID-tree kill, no taskkill /T, and no deleting directories while known live owned descendants remain. Unknown/foreign PID or listener rebound never permits termination of the foreign process. Include browser/setup/check subprocesses in this protocol before claiming complete owner-kill cleanup; current finally-based browser cleanup alone is insufficient.

Automatic teardown means safe stop plus release ephemeral port reservations after positively proving owned processes/listeners are gone. Keep branch refs, source attempt, logs, check rows and browser bytes for `labs.keep_task_worktrees_days`; mark phase=retained and forbid restart. Finished stopped ephemeral records must no longer count toward max_active (otherwise the existing nondestroyed count exhausts after a few tasks); active/cleanup_blocked attempts count, and max_services/ports remain enforced. Retention uses exact registered attempt/lab identity, ended task ancestry and no active merge references, checks cleanliness, process proof and paths again. Cleanup_blocked keeps reservations and artifacts, surfaces an actionable failure, and is never silently pruned.

Do not call ordinary destroyLab immediately after verification because it deletes check PNGs. Extend retained task-Lab prune to remove only that Lab's owned worktrees/data/browser profiles after evidence retention; preserve metadata and branch refs. Bound retrieval sizes/hashes as browserArtifact already does, and validate any copied artifacts into ArtifactStore before removing a root. TaskLab.artifactRefs contain sanitized JSON/log refs and screenshot metadata references, never raw screenshots automatically fed into models, private tokens/commands/env/host paths. Existing ArtifactStore.read is not a general bounded binary retrieval API; don't build a public screenshot path on an unchecked readFileSync. Original coding worktree pruning must skip active/cleanup-blocked Lab dependencies and queued/integrating MergeItems.
